# model bundle size audit — 2026-09-19

Continuation of `wasm_size_2026-09-18.md` (which covered the wasm binary). This one sizes the
**model bundles** the page fetches, in both formats: `ZJB1` (lossless f32, the shipped
default) and `ZJB2` (`pack-models --f16`, f32 network weights stored as IEEE-754 halfs —
see `f16_weights_2026-09-19.md` for the parity study; **ZJB1 remains what the site ships**).

Host `dev`. `zenjpegai pack-models` on `~/work/zen/jpeg-ai-reference-software/models`,
model 1. gzip -9 via `gzip`, brotli -q11 via node `zlib` (same invocation as
`web/scripts/build-wasm.sh`). Commit `f877578`.

Notes:

- The common part halves to 54 % raw / 51 % brotli — not 50 % — because its int8
  hyper-scale-decoder tensors and `vr_vec.c` (the f32 table feeding the integer gain stage)
  are copied untouched inside `ZJB2`.
- Compression eats part of the win: brotli on f32 weight bytes already recovers ~9–11 %
  of the raw size, so the f16→brotli saving is ~50 %, not the raw 47 %.
- **Parity verdict (from `f16_weights_2026-09-19.md`): ZJB2 fails the decoder gate on all
  43 real vectors; these numbers are recorded for the decision, not for shipping.**
